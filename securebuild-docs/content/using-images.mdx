# Using Images

This guide covers best practices for pulling, deploying, and managing SecureBuild images in production environments. Understanding the differences between tag-based and digest-based pulls helps ensure reliable, secure deployments.

## Pull Strategies

### Tag-Based vs Digest-Based Pulls

**Tag-Based Pulls:**
```bash
# Using tags - convenient but can change
docker pull cve0.io/nginx:1.24.0
docker pull cve0.io/nginx:latest
```

**Digest-Based Pulls:**
```bash
# Using digests - immutable and precise
docker pull cve0.io/nginx@sha256:abc123def456...
docker pull cve0.io/nginx:1.24.0@sha256:abc123def456...
```

### When to Use Each Approach

| Scenario | Recommended Approach | Reasoning |
|----------|---------------------|-----------|
| **Production Deployments** | Digest-based | Immutable, predictable, audit-friendly |
| **Staging Environments** | Tag-based with version pins | Balance of stability and convenience |
| **Development** | Tag-based with moving tags | Latest features, rapid iteration |
| **CI/CD Pipelines** | Digest-based for promotion | Ensure exact same image across environments |
| **Infrastructure as Code** | Digest-based | Reproducible deployments |

## Production Deployment Patterns

### 1. Immutable Deployments with Digests


### 2. Automated Digest Resolution

```bash
# resolve-digest.sh - Get digest for a tag
#!/bin/bash

get_image_digest() {
    local image_tag=$1

    # Get manifest digest
    digest=$(docker inspect --format='{{index .RepoDigests 0}}' $image_tag 2>/dev/null)

    if [ -z "$digest" ]; then
        # Pull image if not locally available
        docker pull $image_tag >/dev/null
        digest=$(docker inspect --format='{{index .RepoDigests 0}}' $image_tag)
    fi

    echo $digest
}

# Usage example
IMAGE_WITH_DIGEST=$(get_image_digest "cve0.io/nginx:1.24.0")
echo "Deploying: $IMAGE_WITH_DIGEST"

# Update Kubernetes deployment with digest
kubectl patch deployment nginx-app -p "{
    \"spec\": {
        \"template\": {
            \"spec\": {
                \"containers\": [{
                    \"name\": \"nginx\",
                    \"image\": \"$IMAGE_WITH_DIGEST\"
                }]
            }
        }
    }
}"
```

## CI/CD Integration

### 1. GitHub Actions Pipeline

```yaml
# .github/workflows/deploy.yml
name: Deploy Application

on:
  push:
    branches: [main]

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest

    steps:
    - uses: actions/checkout@v3

    - name: Build application image
      run: |
        docker build -t myapp:${{ github.sha }} .

    - name: Get base image digest
      id: base-digest
      run: |
        BASE_DIGEST=$(docker inspect cve0.io/nginx:1.24.0 --format='{{index .RepoDigests 0}}')
        echo "digest=$BASE_DIGEST" >> $GITHUB_OUTPUT

    - name: Security scan
      run: |
        docker run --rm -v /var/run/docker.sock:/var/run/docker.sock \
          anchore/grype:latest myapp:${{ github.sha }}

    - name: Push to registry
      run: |
        echo ${{ secrets.REGISTRY_PASSWORD }} | docker login registry.company.com -u ${{ secrets.REGISTRY_USERNAME }} --password-stdin
        docker tag myapp:${{ github.sha }} registry.company.com/myapp:${{ github.sha }}
        docker push registry.company.com/myapp:${{ github.sha }}

    - name: Get app image digest
      id: app-digest
      run: |
        APP_DIGEST=$(docker inspect registry.company.com/myapp:${{ github.sha }} --format='{{index .RepoDigests 0}}')
        echo "digest=$APP_DIGEST" >> $GITHUB_OUTPUT

    - name: Deploy to staging
      run: |
        kubectl set image deployment/myapp \
          container=${{ steps.app-digest.outputs.digest }} \
          --namespace=staging

    - name: Wait for rollout
      run: |
        kubectl rollout status deployment/myapp -n staging --timeout=300s

    - name: Run integration tests
      run: |
        ./scripts/integration-tests.sh staging

    - name: Deploy to production
      if: success()
      run: |
        kubectl set image deployment/myapp \
          container=${{ steps.app-digest.outputs.digest }} \
          --namespace=production
```

### 2. Jenkins Pipeline

```groovy
// Jenkinsfile
pipeline {
    agent any

    environment {
        REGISTRY = 'cve0.io'
        APP_NAME = 'myapp'
        KUBECONFIG = credentials('kubeconfig')
    }

    stages {
        stage('Build') {
            steps {
                script {
                    // Build application image using SecureBuild base
                    def baseImage = "${REGISTRY}/node:18-alpine"
                    def appImage = "${APP_NAME}:${env.BUILD_ID}"

                    sh "docker build --build-arg BASE_IMAGE=${baseImage} -t ${appImage} ."

                    // Get image digest
                    def digest = sh(
                        script: "docker inspect ${appImage} --format='{{index .RepoDigests 0}}'",
                        returnStdout: true
                    ).trim()

                    env.IMAGE_DIGEST = digest
                }
            }
        }

        stage('Security Scan') {
            steps {
                sh """
                    docker run --rm -v /var/run/docker.sock:/var/run/docker.sock \\
                        anchore/grype:latest ${APP_NAME}:${env.BUILD_ID}
                """
            }
        }

        stage('Deploy to Staging') {
            steps {
                sh """
                    kubectl set image deployment/${APP_NAME} \\
                        container=${env.IMAGE_DIGEST} \\
                        --namespace=staging

                    kubectl rollout status deployment/${APP_NAME} \\
                        -n staging --timeout=300s
                """
            }
        }

        stage('Integration Tests') {
            steps {
                sh './scripts/integration-tests.sh staging'
            }
        }

        stage('Deploy to Production') {
            when {
                branch 'main'
            }
            steps {
                input message: 'Deploy to production?', ok: 'Deploy'

                sh """
                    kubectl set image deployment/${APP_NAME} \\
                        container=${env.IMAGE_DIGEST} \\
                        --namespace=production
                """
            }
        }
    }

    post {
        always {
            sh 'docker system prune -f'
        }
    }
}
```

## Caching and Performance

### 1. Registry Proxy/Cache

```yaml
# registry-proxy.yaml - Local registry cache
apiVersion: apps/v1
kind: Deployment
metadata:
  name: registry-proxy
spec:
  replicas: 1
  selector:
    matchLabels:
      app: registry-proxy
  template:
    metadata:
      labels:
        app: registry-proxy
    spec:
      containers:
      - name: registry
        image: registry:2.8
        env:
        - name: REGISTRY_PROXY_REMOTEURL
          value: "https://cve0.io"
        - name: REGISTRY_PROXY_USERNAME
          valueFrom:
            secretKeyRef:
              name: registry-credentials
              key: username
        - name: REGISTRY_PROXY_PASSWORD
          valueFrom:
            secretKeyRef:
              name: registry-credentials
              key: password
        ports:
        - containerPort: 5000
        volumeMounts:
        - name: registry-storage
          mountPath: /var/lib/registry
      volumes:
      - name: registry-storage
        persistentVolumeClaim:
          claimName: registry-storage-pvc
```

### 2. Docker Layer Caching

```bash
# Enable Docker BuildKit for better caching
export DOCKER_BUILDKIT=1

# Use cache mounts in Dockerfile
FROM cve0.io/node:18-alpine

# Cache node_modules
RUN --mount=type=cache,target=/root/.npm \
    npm ci --only=production

# Cache go modules
FROM cve0.io/golang:1.21
RUN --mount=type=cache,target=/go/pkg/mod \
    go mod download
```

### 3. Multi-Stage Build Caching

```dockerfile
# Optimized multi-stage build with caching
FROM cve0.io/node:18-alpine AS dependencies

WORKDIR /app

# Copy package files first for better caching
COPY package*.json ./
RUN npm ci --only=production && npm cache clean --force

# Build stage
FROM cve0.io/node:18-alpine AS builder

WORKDIR /app

# Copy package files and install all dependencies
COPY package*.json ./
RUN npm ci

# Copy source and build
COPY . .
RUN npm run build

# Production stage
FROM cve0.io/node:18-alpine AS production

WORKDIR /app

# Copy production dependencies from cache stage
COPY --from=dependencies /app/node_modules ./node_modules

# Copy built application
COPY --from=builder /app/dist ./dist
COPY package.json ./

USER 1001

CMD ["node", "dist/index.js"]
```

## Image Verification

### 1. Signature Verification with Cosign

```bash
# Install cosign
curl -O -L "https://github.com/sigstore/cosign/releases/latest/download/cosign-linux-amd64"
sudo mv cosign-linux-amd64 /usr/local/bin/cosign
sudo chmod +x /usr/local/bin/cosign

# Verify SecureBuild image signature
cosign verify cve0.io/nginx:1.24.0 \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  --certificate-identity-regexp 'https://github.com/securebuildhq/.*'

# Verify with public key (if using key-based signing)
cosign verify cve0.io/nginx:1.24.0 \
  --key securebuild-public.key
```

### 2. SBOM Verification

```bash
# Download and verify SBOM
cosign download sbom cve0.io/nginx:1.24.0 > nginx-sbom.json

# Validate SBOM format
spdx-tools validate nginx-sbom.json

# Analyze dependencies
grype sbom:nginx-sbom.json

# Check for specific components
jq '.packages[] | select(.name | contains("openssl"))' nginx-sbom.json
```

### 3. Provenance Verification

```bash
# Download provenance attestation
cosign download attestation cve0.io/nginx:1.24.0 > nginx-provenance.json

# Verify build provenance
jq '.payload | @base64d | fromjson' nginx-provenance.json

# Check build details
jq '.payload | @base64d | fromjson | .predicate.buildConfig' nginx-provenance.json
```

## Monitoring and Observability

### 1. Image Usage Tracking

```yaml
# prometheus-monitoring.yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: prometheus-config
data:
  prometheus.yml: |
    global:
      scrape_interval: 15s

    rule_files:
      - "image_rules.yml"

    scrape_configs:
    - job_name: 'kubernetes-pods'
      kubernetes_sd_configs:
      - role: pod
      relabel_configs:
      - source_labels: [__meta_kubernetes_pod_annotation_prometheus_io_scrape]
        action: keep
        regex: true

---
apiVersion: v1
kind: ConfigMap
metadata:
  name: image-rules
data:
  image_rules.yml: |
    groups:
    - name: image_usage
      rules:
      - alert: UnsignedImageUsed
        expr: |
          kube_pod_container_info{image!~"registry\\.securebuild\\.io/.*"} > 0
        for: 0m
        labels:
          severity: warning
        annotations:
          summary: "Unsigned image in use"
          description: "Pod {{ $labels.pod }} is using unsigned image {{ $labels.image }}"

      - alert: OutdatedImageUsed
        expr: |
          (time() - kube_pod_container_info_created) > (7 * 24 * 3600)
        for: 0m
        labels:
          severity: info
        annotations:
          summary: "Image older than 7 days"
          description: "Pod {{ $labels.pod }} is using image older than 7 days"
```

### 2. Image Vulnerability Monitoring

```bash
# continuous-scanning.sh
#!/bin/bash

# Monitor running containers for vulnerabilities
kubectl get pods --all-namespaces -o json | \
  jq -r '.items[] | .spec.containers[] | .image' | \
  sort -u | \
  while read image; do
    echo "Scanning $image..."
    grype $image --output json > "scan-$(echo $image | tr '/' '-' | tr ':' '-').json"
  done

# Alert on critical vulnerabilities
find . -name "scan-*.json" -exec jq -r '
  select(.matches[] | select(.vulnerability.severity == "Critical")) |
  "CRITICAL: " + .source.target + " has critical vulnerabilities"
' {} \;
```

## Troubleshooting

### 1. Pull Issues

```bash
# Debug image pull problems
kubectl describe pod <pod-name>

# Check image pull secrets
kubectl get secrets -n <namespace>
kubectl describe secret <secret-name>

# Test manual pull
docker pull cve0.io/nginx:1.24.0

# Check registry connectivity
curl -v https://cve0.io/v2/

# Verify credentials
docker login cve0.io --username <username>
```

### 2. Digest Resolution Issues

```bash
# Get current digest for a tag
docker pull cve0.io/nginx:1.24.0
docker inspect cve0.io/nginx:1.24.0 --format '{{index .RepoDigests 0}}'

# Compare digests
CURRENT_DIGEST=$(docker inspect nginx:1.24.0 --format '{{index .RepoDigests 0}}')
EXPECTED_DIGEST="cve0.io/nginx@sha256:abc123..."

if [ "$CURRENT_DIGEST" != "$EXPECTED_DIGEST" ]; then
  echo "Digest mismatch detected!"
  echo "Current: $CURRENT_DIGEST"
  echo "Expected: $EXPECTED_DIGEST"
fi
```

### 3. Performance Issues

```bash
# Monitor image pull performance
time docker pull cve0.io/nginx:1.24.0

# Check layer caching
docker history cve0.io/nginx:1.24.0

# Analyze image size
docker images cve0.io/nginx:1.24.0 --format "table {{.Repository}}\t{{.Tag}}\t{{.Size}}"

# Check network connectivity
curl -w "@curl-format.txt" -o /dev/null -s https://cve0.io/v2/nginx/manifests/1.24.0
```

## Best Practices Summary

### Production Deployments
- ✅ Use digest-based image references
- ✅ Implement image signature verification
- ✅ Configure proper RBAC and image pull secrets
- ✅ Monitor image vulnerabilities continuously
- ✅ Use non-root users and security contexts

### Development Workflows
- ✅ Use tag-based pulls for rapid iteration
- ✅ Implement automated security scanning
- ✅ Cache images and layers for performance
- ✅ Validate images before promotion

### CI/CD Integration
- ✅ Resolve digests in build pipelines
- ✅ Store image metadata for auditing
- ✅ Implement automated rollback on failures
- ✅ Test image security and functionality

By following these practices, you'll ensure secure, reliable, and efficient use of SecureBuild images across your infrastructure.
