## Rebuilding Strategies

### 1. Automated Rebuilds

**CI/CD Integration:**
```yaml
# .github/workflows/rebuild-on-updates.yml
name: Rebuild on Base Image Updates

on:
  repository_dispatch:
    types: [base-image-updated]
  schedule:
    # Check for updates daily
    - cron: '0 6 * * *'

jobs:
  rebuild:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Setup Docker Buildx
        uses: docker/setup-buildx-action@v3

      - name: Login to Registry
        uses: docker/login-action@v3
        with:
          registry: your-registry.io
          username: ${{ secrets.DOCKER_USERNAME }}
          password: ${{ secrets.DOCKER_PASSWORD }}

      - name: Check for base image updates
        id: updates
        run: |
          # Check if base image has been updated
          CURRENT_DIGEST=$(docker manifest inspect cve0.io/node:20 | jq -r '.config.digest')
          LAST_DIGEST=$(cat .last-digest 2>/dev/null || echo "")

          if [ "$CURRENT_DIGEST" != "$LAST_DIGEST" ]; then
            echo "update=true" >> $GITHUB_OUTPUT
            echo "$CURRENT_DIGEST" > .last-digest
          else
            echo "update=false" >> $GITHUB_OUTPUT
          fi

      - name: Build and push updated image
        if: steps.updates.outputs.update == 'true'
        uses: docker/build-push-action@v5
        with:
          context: .
          push: true
          tags: |
            your-registry.io/your-app:latest
            your-registry.io/your-app:$(date +%Y%m%d)
          cache-from: type=gha
          cache-to: type=gha,mode=max
```

### 2. Scheduled Rebuilds

**Weekly Security Rebuilds:**
```bash
#!/bin/bash
# weekly-rebuild.sh

echo "Checking for base image updates..."

# Pull latest base images
docker pull cve0.io/node:20
docker pull cve0.io/python:3.11

# Get current image digests
NODE_DIGEST=$(docker inspect cve0.io/node:20 | jq -r '.[0].RepoDigests[0]')
PYTHON_DIGEST=$(docker inspect cve0.io/python:3.11 | jq -r '.[0].RepoDigests[0]')

# Compare with stored digests
if [ "$NODE_DIGEST" != "$(cat .node-digest 2>/dev/null)" ]; then
  echo "Node.js base image updated, rebuilding applications..."

  # Rebuild Node.js applications
  docker build -t your-app:$(date +%Y%m%d) .
  docker tag your-app:$(date +%Y%m%d) staging.registry.io/your-app:latest
  docker push staging.registry.io/your-app:latest

  # Store new digest
  echo "$NODE_DIGEST" > .node-digest

  # Notify team
  curl -X POST -H 'Content-type: application/json' \
    --data '{"text":"Node.js base image updated, applications rebuilt"}' \
    $SLACK_WEBHOOK_URL
fi
```

### 3. Emergency Security Rebuilds

**Critical CVE Response:**
```bash
#!/bin/bash
# emergency-rebuild.sh

echo "Emergency rebuild triggered for security updates"

# Force pull latest base images (bypass cache)
docker pull --platform=linux/amd64 cve0.io/node:20
docker pull --platform=linux/arm64 cve0.io/node:20

# Build multi-arch images immediately
docker buildx build --platform linux/amd64,linux/arm64 \
  --tag production.registry.io/your-app:emergency-$(date +%Y%m%d-%H%M) \
  --push .

# Alert operations team
curl -X POST "https://api.pagerduty.com/incidents" \
  -H "Authorization: Token token=$PAGERDUTY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "incident": {
      "type": "incident",
      "title": "Emergency image rebuild completed",
      "service": {
        "id": "'$SERVICE_ID'",
        "type": "service_reference"
      }
    }
  }'
```

## Best Practices

### 1. Multi-Stage Build Optimization

**Minimize Runtime Dependencies:**
```dockerfile
# ✅ Good: Separate build and runtime stages
FROM node:20-alpine AS builder
# ... build steps ...

FROM cve0.io/node:20
# Only copy what's needed for runtime

# ❌ Bad: Single stage with build tools in runtime
FROM cve0.io/node:20
RUN apk add --no-cache git build-essential  # Unnecessary in runtime
```

**Layer Optimization:**
```dockerfile
# ✅ Good: Copy dependencies first (better caching)
COPY package*.json ./
RUN npm install
COPY . .

# ❌ Bad: Copy everything first (breaks caching)
COPY . .
RUN npm install
```

### 2. Security Hardening

**Use Non-Root Users:**
```dockerfile
# ✅ Good: Run as non-root user
FROM cve0.io/node:20
USER 1000:1000
WORKDIR /app

# ❌ Bad: Running as root
FROM cve0.io/node:20
USER root
```

**Minimize Attack Surface:**
```dockerfile
# ✅ Good: Only copy production files
COPY --from=builder /app/dist ./dist
COPY --from=builder /app/node_modules ./node_modules

# ❌ Bad: Copy source code and build tools
COPY . .
```

### 3. Monitoring & Maintenance

**Image Scanning:**
```bash
# Scan your built images
docker scout cves your-app:latest

# Check for base image updates
docker scout quickview cve0.io/node:20
```

**Automated Testing:**
```dockerfile
# Add health checks to your images
HEALTHCHECK --interval=30s --timeout=3s --start-period=5s --retries=3 \
  CMD curl -f http://localhost:3000/health || exit 1
```

## Getting Started

### 1. Set Up Your Development Environment

```bash
# Pull a SecureBuild base image
docker pull cve0.io/node:20

# Verify the image
docker run --rm cve0.io/node:20 node --version
```

### 2. Create Your First Multi-Stage Build

```bash
# Create a simple Node.js app
mkdir my-secure-app && cd my-secure-app

# Create package.json
cat > package.json << EOF
{
  "name": "my-secure-app",
  "version": "1.0.0",
  "scripts": {
    "start": "node server.js"
  },
  "dependencies": {
    "express": "^4.18.0"
  }
}
EOF

# Create server.js
cat > server.js << EOF
const express = require('express');
const app = express();
const port = 3000;

app.get('/', (req, res) => {
  res.json({ message: 'Hello from SecureBuild!' });
});

app.listen(port, () => {
  console.log(\`Server running on port \${port}\`);
});
EOF

# Create Dockerfile
cat > Dockerfile << EOF
FROM node:20-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .

FROM cve0.io/node:20
USER 1000:1000
WORKDIR /app
COPY --from=builder --chown=1000:1000 /app .
EXPOSE 3000
CMD ["npm", "start"]
EOF

# Build and test
docker build -t my-secure-app .
docker run --rm -p 3000:3000 my-secure-app
```
