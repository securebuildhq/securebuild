# Image Tagging

SecureBuild follows a simple, predictable tagging strategy: **we mirror the tagging approach of the upstream project**. This ensures familiarity and consistency with the images you already know and use.

## Tagging Philosophy

### Mirror Upstream Strategy

SecureBuild doesn't invent its own tagging schemes. Instead, we:

- **Follow the official image's tags** - If nginx uses `latest`, `1.25`, `1.25.3`, so do we
- **Match popular conventions** - We adopt the most common tagging pattern for each project
- **Maintain compatibility** - Your existing image references work the same way

### OS Variants: What We Don't Mirror

Many official images provide multiple operating system variants:

```bash
# Common OS variants in official images
nginx:latest              # Default (usually Debian-based)
nginx:alpine              # Alpine Linux variant
nginx:debian              # Explicit Debian variant
nginx:ubuntu              # Ubuntu variant
```

**SecureBuild does not mirror these OS variants** because we rebuild everything on our own secure, minimal base:

- **SecureOS-based foundation** - All SecureBuild images use SecureOS as the base OS
- **Single, secure base** - No need for multiple OS variants when we control the entire stack
- **Smaller attack surface** - Fewer variants means better security focus and maintenance

### What This Means for You

When migrating to SecureBuild, you'll need to adjust image references that use OS variants:

```bash
# Original references
nginx:alpine          # ❌ Not available
postgres:16-alpine    # ❌ Not available
redis:7-debian        # ❌ Not available

# SecureBuild equivalents
cve0.io/nginx:latest      # ✅ SecureOS-based, minimal and secure
cve0.io/postgres:16       # ✅ Same functionality, better security
cve0.io/redis:7           # ✅ Optimized and hardened
```

### Why SecureOS Is Better

Our SecureOS-based approach provides advantages over traditional OS variants:

- **Minimal footprint** - Only packages needed for the application
- **No package manager** - Reduces attack surface (no apt, yum, etc.)
- **Latest security patches** - Rebuilt frequently with current fixes
- **Glibc compatibility** - Works with existing applications (unlike musl-based Alpine)
- **Supply chain security** - Every package is built from source with verification

### Example Tag Mirroring

```bash
# Official nginx image tags
nginx:latest
nginx:1.25
nginx:1.25.3
nginx:alpine
nginx:1.25-alpine

# SecureBuild mirrors exactly
cve0.io/nginx:latest
cve0.io/nginx:1.25
cve0.io/nginx:1.25.3
```

## Release-Based Tagging

### We Follow Stable Releases

SecureBuild tracks **stable releases** from upstream projects, not individual commits:

- ✅ **Official releases** - Tagged versions like `v1.25.3`
- ✅ **Stable branches** - Major/minor versions like `1.25`
- ✅ **LTS versions** - Long-term support releases
- ❌ **Development commits** - We don't tag every commit
- ❌ **Experimental builds** - Only stable, released versions


## Mutable Tags

### Tags Update When Dependencies Change

**Important**: SecureBuild tags are **mutable** - they change when we rebuild with updated dependencies.

```bash
# Same tag, different content over time
nginx:1.25.3  # Today: Built with OpenSSL 3.1.0
# ... security update to OpenSSL 3.1.1 ...
nginx:1.25.3  # Tomorrow: Rebuilt with OpenSSL 3.1.1
```

### Why Tags Change

We rebuild and push over existing tags when:

- **Security updates** - CVE fixes in base packages
- **Dependency updates** - New versions of libraries (OpenSSL, glibc, etc.)
- **Base image updates** - Newer Alpine or SecureOS base
- **Build toolchain improvements** - Better security hardening

### Tracking Changes

Since tags are mutable, here's how to track what actually changed:

#### 1. Image Digests
```bash
# Check the digest to see if content changed
docker inspect cve0.io/nginx:1.25.3 --format '{{.RepoDigests}}'

# Before: sha256:abc123...
# After:  sha256:def456...  (content changed!)
```

#### 2. Notifications
Set up monitoring in the [SecureBuild Application](https://securebuild.com) to get alerts when images are updated:

- Navigate to your image in the UI
- Enable notifications for security updates
- Configure webhooks or email alerts
- You'll get alerts like: "nginx:1.25.3 rebuilt with OpenSSL 3.1.1 (CVE-2023-1234 fix)"

#### 3. SBOM and Revision Tracking
```bash
# Generate SBOM to see package versions
syft cve0.io/nginx:1.25.3

# Scan for vulnerabilities
grype cve0.io/nginx:1.25.3

# Compare SBOMs over time to see revision bumps:
# openssl: 3.1.0-r1 → 3.1.1-r1
# nginx:   1.25.3-r1 → 1.25.3-r2  (rebuilt)
```

## Version Discovery

### Finding Available Tags

You can discover available tags through the [SecureBuild catalog](https://securebuild.com/images) or using standard registry tools. For example, on the image details Tags section all available tags are clearly shown at [https://securebuild.com/images/nginx/inspect/tags](https://securebuild.com/images/nginx/inspect/tags):

```bash
# List tags using Docker/registry API
curl -s https://cve0.io/v2/nginx/tags/list | jq '.tags[]'

# Or use crane (from go-containerregistry)
crane ls cve0.io/nginx

# Output shows available tags:
# latest
# 1.25
# 1.25.3
# 1.24
```

### Tag History and Changes

Track changes through the SecureBuild UI or by comparing image digests and SBOMs over time:

```bash
# Check current digest
docker image inspect cve0.io/nginx:1.25.3 --format '{{.Id}}'

# Generate SBOM and save for comparison
syft cve0.io/nginx:1.25.3 -o json > nginx-1.25.3-$(date +%Y%m%d).json

# Later, compare with new SBOM to see what changed
# - OpenSSL updated for security patch
# - Package revisions bumped (r1 → r2)
```

## Best Practices

### For Production

1. **Monitor Notifications**: Set up monitoring in the [SecureBuild UI](https://securebuild.com)
   - Navigate to your images and enable notifications
   - Configure webhooks for automated alerts
   - Monitor security updates and dependency changes

2. **Pin by Digest**: For critical deployments, pin the exact digest
   ```yaml
   # kubernetes deployment
   image: cve0.io/nginx@sha256:abc123...  # Exact content
   ```

3. **Check SBOMs**: Verify security updates are applied
   ```bash
   # Generate SBOM to see current packages
   syft cve0.io/nginx:1.25.3

   # Scan for vulnerabilities
   grype cve0.io/nginx:1.25.3
   ```

### For Development

1. **Use Version Tags**: Prefer `cve0.io/nginx:1.25` over `cve0.io/nginx:latest`
2. **Expect Updates**: Remember tags change with security updates
3. **Test Regularly**: Updates might affect your application

### Monitoring Changes

Set up monitoring through the SecureBuild UI:

1. **Go to [securebuild.com](https://securebuild.com)**
2. **Find your image** (e.g., nginx:1.25.3)
3. **Enable notifications** for:
   - Security updates
   - Dependency changes
   - New vulnerabilities
4. **Configure alerts**:
   - Email notifications
   - Webhook URLs for automated handling
   - Slack/Discord integrations

## Why This Approach

### Familiar and Predictable
- **No learning curve** - Same tags you already use
- **Drop-in replacement** - Change only the registry URL
- **Industry standard** - Follows established conventions

### Security Without Disruption
- **Automatic updates** - Security fixes applied transparently
- **Controlled changes** - Only stable releases, not random commits
- **Full visibility** - Notifications and SBOM tracking show what changed

### Simplified Operations
- **One tagging strategy** - Same approach for all images
- **Clear expectations** - Tags update, digests don't
- **Easy migration** - Minimal changes to existing workflows
